# Application Menus Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an application declare its own menu bar — top-level menus, items bound to Java methods, separators, and keyboard shortcuts — and have it work identically on macOS and Windows.

**Architecture:** A portable model in the framework's root package (`Menus`, `MenuBar`, `Menu`, `Item`, `Platform`) describes the menu. The portable layer owns a `name → id` table; each platform builds its own native menu from the model and reports a click as an integer id through a new `UiHost.Callbacks.onMenuItem(int)`. The portable layer maps the id back to a name and invokes the binding the same way a page call does.

**Tech Stack:** Java 25, `java.lang.foreign` (FFM), AppKit (`NSMenu`/`NSMenuItem`) on macOS, Win32 (`HMENU`/`WM_COMMAND`) on Windows, JUnit 5 for the CI-runnable half.

**Spec:** `docs/superpowers/specs/2026-10-21-app-menus-design.md` — the plan argues from the spec, so the spec travels with it; executors read both.

## Global Constraints

- The framework has **zero runtime dependencies**. JUnit is `test` scope only, in `framework/pom.xml` version `5.12.0`; surefire is version `3.5.2`.
- `WindowSpec` and `UiHost` are **published public types** and must not gain components or abstract methods. The menu reaches a host through a **new** optional interface.
- `UiHost.Callbacks` may only grow **`default`** methods.
- The framework's runtime dependencies stay empty; the published jar carries no application classes and no pages.
- Java 25. `maven.compiler.release` is 25 in the parent pom.
- Code comments explain *why*, not *what*, and the repository's existing voice is kept: measured facts, plain words, no filler.
- Every new downcall or upcall shape used on macOS must be present in `framework/src/main/resources/META-INF/native-image/io.github.lihuu/panamaview/reachability-metadata.json`, or a native build dies at run time with `MissingForeignRegistrationError`.
- Shell scripts are linted by `scripts/lint.sh` (shellcheck 0.11.0). Batch and PowerShell files are not linted.
- **Windows keyboard shortcuts are out of scope for this plan.** The first slice delivers a clickable menu bar on both platforms; macOS additionally gets shortcuts because its menu item already carries them. The Windows accelerator route is separate work.

## Review Focus

These are the input classes and failure modes the spec implies but the tasks' tests do not obviously cover. Each one gets a test in the task that owns the code.

1. **A menu item naming a binding that was never declared.** The click must not be a silent no-op — the framework reports it (stderr, `[panamaview]` prefix), and no other action fires.
2. **A menu item naming a `bindUi` binding.** It must be refused: a UI-thread binding would run inline on the UI thread with no deadline, and a menu click already arrives there.
3. **A separator or a popup being "clicked".** A separator's id is `0` and a popup's is `0xFFFFFFFF`; neither may be looked up as a binding, and neither may reach the page as a stray JavaScript evaluation.
4. **A binding that throws when a menu item invokes it.** Reported like any other framework-level failure, and the *next* menu item still works — one bad action must not stop the queue.
5. **A menu item whose title is non-ASCII** (「导出」, 「文件」). Must round-trip through both platforms' UTF-16 string handling, and must not be mojibake in the menu.
6. **A menu declared but the host cannot take one** (a `UiHost` that does not implement `MenuHost`). The application must still run — no menu, no failure.

- [ ] **Step 3: Implement the model**

`Item.java` — one file, three implementations, because they are one concept split three ways.
**The nested names are `BindingItem`, `PlatformItem` and `SeparatorItem`, not `Binding`,
`Platform` and `Separator`.** `Platform` is already the name of the enum, and a nested type
called `Platform` would shadow it inside `Item.java` — so `Platform platformAction()` would
resolve to the record rather than the enum.

```java
public sealed interface Item permits Item.BindingItem, Item.PlatformItem, Item.SeparatorItem {
    String title();
    String binding();          // null unless this is a BindingItem
    Platform platformAction(); // null unless this is a PlatformItem
    Shortcut shortcut();
    Item shortcut(Shortcut s);
    int id();
    void assignId(int id);

    final class BindingItem implements Item { … }
    final class PlatformItem implements Item { … }
    final class SeparatorItem implements Item { … }
}
```

**The three implementations are small classes, not records**, and that is forced rather than
chosen: the id is assigned when the bar is walked, which is *after* the item is built, and a
record's accessor is final with no wither in Java — so a record could not carry an id
assigned later. Each implementation holds `id` in a field, and `assignId` sets it.

`Item.BindingItem` and `Item.PlatformItem` both need `binding()` and `platformAction()` to
answer `null` for the other kind, and `Item.SeparatorItem` answers `null` for both.
`shortcut(Shortcut s)` sets the shortcut and returns `this`, so it chains.

`Shortcut.parse(String)` — the format is modifiers joined by `+`, then the key. `CmdOrCtrl` is a modifier of its own; `Ctrl`, `Shift` and `Alt` are the others. Parsing is case-insensitive for the modifier names, and the key keeps its case. An unparseable string throws `IllegalArgumentException` naming the string.

class MenuBindingTest {

    /** A host that takes a menu and remembers the callback. */
    private static final class RecordingHost implements UiHost, MenuHost {
        UiHost.Callbacks callbacks;
        MenuBar bar;

        @Override public void start(Callbacks c, WindowSpec spec) { this.callbacks = c; }
        @Override public void evaluate(String script) { }
        @Override public void onUiThread(Runnable action) { action.run(); }
        @Override public boolean isUiThread() { return true; }
        @Override public void setMenu(MenuBar bar) { this.bar = bar; }
    }

    /** A host that takes no menu at all. */
    private static final class PlainHost implements UiHost {
        UiHost.Callbacks callbacks;

        @Override public void start(Callbacks c, WindowSpec spec) { this.callbacks = c; }
        @Override public void evaluate(String script) { }
        @Override public void onUiThread(Runnable action) { action.run(); }
        @Override public boolean isUiThread() { return true; }
    }

    @Test
    void aClickInvokesTheBindingItNames() {
        var host = new RecordingHost();
        var calls = new AtomicInteger();
        var app = new WebApp(host).bind("export", params -> { calls.incrementAndGet(); return "exported"; });
        app.menu(Menus.menu(Menus.menu("文件", Menus.item("export", "导出"))));
        app.run();

        // The bar reached the host.
        assertNotNull(host.bar);

        // Clicking item 1 is a call to the "export" binding.
        host.callbacks.onMenuItem(1);
        assertEquals(1, calls.get(), "the binding named by the clicked item must run");
    }

    @Test
    void aClickOnAnUndeclaredBindingRunsNothingAndDoesNotThrow() {
        var host = new RecordingHost();
        var app = new WebApp(host);
        app.menu(Menus.menu(Menus.menu("文件", Menus.item("export", "导出"))));
        app.run();

        // The framework reports it; it does not throw, and it does not run anything.
        assertDoesNotThrow(() -> host.callbacks.onMenuItem(1));
    }

    @Test
    void aMenuItemMayNotNameAUiThreadBinding() {
        var host = new RecordingHost();
        var calls = new AtomicInteger();
        var app = new WebApp(host).bindUi("export", params -> { calls.incrementAndGet(); return null; });
        app.menu(Menus.menu(Menus.menu("文件", Menus.item("export", "导出"))));
        app.run();

        // A UI-thread binding has no deadline and would run inline on the UI thread, which is
        // where a menu click already is. The framework refuses it.
        assertDoesNotThrow(() -> host.callbacks.onMenuItem(1));
        assertEquals(0, calls.get(), "a bindUi binding must not run from a menu item");
    }

    @Test
    void aThrowingBindingDoesNotStopTheNextOne() {
        var host = new RecordingHost();
        var calls = new AtomicInteger();
        var app = new WebApp(host)
                .bind("boom", params -> { throw new IllegalStateException("boom"); })
                .bind("after", params -> { calls.incrementAndGet(); return "ok"; });
        app.menu(Menus.menu(Menus.menu("文件",
                Menus.item("boom", "爆炸"),
                Menus.item("after", "之后"))));
        app.run();

        assertDoesNotThrow(() -> host.callbacks.onMenuItem(1));
        host.callbacks.onMenuItem(2);
        assertEquals(1, calls.get(), "one bad action must not strand the ones after it");
    }

    @Test
    void aHostThatTakesNoMenuStillRuns() {
        var host = new PlainHost();
        var app = new WebApp(host).bind("greet", params -> "hi");
        app.menu(Menus.menu(Menus.menu("文件", Menus.item("greet", "你好"))));

        // The application declared a menu and the host cannot take one. The application runs.
        assertDoesNotThrow(app::run);
        assertNotNull(host.callbacks);
    }
}

```java
/**
 * A menu item was chosen, identified by the id the framework gave it.
 *
 * <p>Optional: a host with no menu has nothing to report, and a default method keeps every
 * existing implementation of this interface working.

default void onMenuItem(int id) {

`Bridge` gains a way to run a named binding outside the page path. It reuses the existing
`Binding` record and the existing `run` machinery, so a menu binding is dispatched exactly as a
page call is: on a virtual thread, with the binding's own deadline, cancellable. An unknown

**The id → name mapping lives in the portable layer**, because both platforms identify an item
by an integer and the name is the framework's own bookkeeping. The ids are assigned while the
bar is walked, in the order the items appear, starting at **1** — 0 is what a separator reports
and `0xFFFFFFFF` is what a popup reports, so neither may name a binding.

- [ ] **Step 3: Implement `MenuTarget`**

A runtime Objective-C class whose single method is an FFM upcall into Java. It is the
**target** of every binding item, and the item's `tag` carries the id.

The method is `- (void)panamaviewMenuItem:(id)sender` — receiver, selector, one object
argument — so the descriptor is `ObjC.VOID1` (three pointers), **not** `VOID2` (four). The
encoding is `v@:@`. `ObjC.VOID1` is private today and becomes package-private.

The instance is held in a **static field**, because `NSMenuItem.target` is a *weak* reference: a
target Java's collector reclaims becomes nil, and a nil target is exactly the *platform item*
behaviour — a binding item would quietly stop being one. `ObjCDispatch` keeps its instance in a
static field for the same reason (ObjCDispatch.java:45).

The method reads the id off the sender's `tag` and hands it to the host.

- [ ] **Step 4: Implement the `NSMenu` builder in `Cocoa`**

`Cocoa` gains a method that walks the model and builds the `NSMenu`:

- A **bar** is an `NSMenu`; a **top-level menu** joins it through a menu item that holds it as
  its submenu, and that item carries the title the user sees.
- A **binding item** is an `NSMenuItem` with the shared target, the action selector
  `panamaviewMenuItem:`, and its `tag` set to the id.
- A **platform item** is an `NSMenuItem` with a **nil target** and the action selector for its
  `Platform` operation — `terminate:` for QUIT, `undo:` for UNDO, `redo:` for REDO,
  `cut:` for CUT, `copy:` for COPY, `paste:` for PASTE, `selectAll:` for SELECT_ALL.
- A **separator** is `+[NSMenuItem separatorItem]`, a class-method singleton.
- The **shortcut** goes in the item's `keyEquivalent` (the character) and
  `keyEquivalentModifierMask` (the modifiers). The mask is set **always**, including when there
  are no modifiers — AppKit's default for a bare key equivalent is Command, so leaving the mask
  alone would turn `"C"` into ⌘C.

`Cocoa.installMenuBar` — the framework's existing, hard-coded main menu — is replaced by the
builder, because the model's `appMenu()` and `editMenu()` produce the same two menus and the
application's own bar replaces them.

The `Platform` operation → macOS selector mapping:

| Platform | selector |
| :--- | :--- |
| `QUIT` | `terminate:` |
| `UNDO` | `undo:` |
| `REDO` | `redo:` |
| `CUT` | `cut:` |
| `COPY` | `copy:` |
| `PASTE` | `paste:` |
| `SELECT_ALL` | `selectAll:` |

            "a separator still takes an id, so the ids after it are not shifted");
    assertEquals(3, bar.menus().get(0).items().get(2).id());
}
```

**And the two "not an id" values are about the id that *arrives*, not the one the
framework assigned.** The framework's own ids start at 1 and a separator takes one, like any
other item — it is the *click* on a separator that reports 0, and the click on a popup that
reports `0xFFFFFFFF`. So the guard is on the arriving id, and it is the Windows side that
sees it:

```java
@Test
void aSeparatorStillTakesAnId() {
    // The separator's assigned id is a real one, so the ids after it are not shifted. What
    // arrives when a separator is clicked is 0 — that is the Windows side's business.
    var bar = Menus.menu(Menus.menu("文件",
            Menus.item("export", "导出"),
            Menus.separator()));
    assertEquals(1, bar.menus().get(0).items().get(0).id());
    assertEquals(2, bar.menus().get(0).items().get(1).id());
}
```

`Item.id()` is the id the framework assigns the item, and it is part of the model — the
platform puts it in the item's `tag` on macOS and in `uIDNewItem` on Windows, and the
portable layer maps it back.

Run: `mvn -B -pl framework test -Dtest=MenuModelTest`
Expected: FAIL — nothing assigns the ids yet.

- [ ] **Step 3: Bind the Win32 menu functions**

`Win32` gains three bindings and two constants:

| function | signature |
| :--- | :--- |
| `CreateMenu` | `HMENU CreateMenu(void)` — no arguments |
| `AppendMenuW` | `BOOL AppendMenuW(HMENU, UINT flags, UINT_PTR id, LPCWSTR text)` — **four** parameters |
| `DestroyMenu` | `BOOL DestroyMenu(HMENU)` — one parameter |

`AppendMenuW`'s third parameter is a `UINT_PTR` — a pointer-sized integer, so `ADDRESS` in FFM
terms, not `JAVA_INT` — and it carries **two** different things: the command id for an ordinary
item, and the submenu handle when `MF_POPUP` is set.

The flag values:

| flag | value | |
| :--- | :--- | :--- |
| `MF_STRING` | `0x00000000` | the text is a string — **the absence of a flag**, not a bit to set |
| `MF_POPUP` | `0x00000010` | `uIDNewItem` is an `HMENU`, not a command id |
| `MF_SEPARATOR` | `0x00000800` | the text and the id are both ignored |

- [ ] **Step 4: Implement `WinMenu`**

Builds the `HMENU` from the model: the bar is an `HMENU`; a top-level menu is an item with
`MF_POPUP` whose `uIDNewItem` is the submenu's handle; a binding item is an item with
`MF_STRING` and the command id; a platform item is an item with `MF_STRING` and a command id
that the host recognises; a separator is an item with `MF_SEPARATOR`.

Strings are allocated with `allocateFrom(text, StandardCharsets.UTF_16LE)`, which adds the
null terminator — the pattern `Win32` already uses for window titles.

- [ ] **Step 5: Attach the menu at window creation**

`Win32.createWindow` grows a parameter for the `HMENU`, because `CreateWindowExW`'s tenth
parameter is `hMenu` and the binding already has all twelve. **The menu goes in at creation
time**, not through `SetMenu` afterwards: `createWindow` calls `ShowWindow` internally, so a
menu attached afterwards would land on an already-visible window and the window would flash up
without its menu.

`WindowsHost` grows the `hMenu` parameter through to the `createWindow` call, and answers
`WM_COMMAND`:

- the high word of `wParam` must be **0** — a menu. An accelerator is 1, and a control
  notification is whatever the control defines, so a control whose identifier collides with a
  menu item's must not fire that item's binding.
- the low word is the id. **0 and `0xFFFFFFFF` are not ids**: 0 is what a separator reports and
  `0xFFFFFFFF` is what a popup reports. Neither may be looked up.

Run: `mvn -B -pl framework test -Dtest=MenuModelTest`
Expected: PASS.
